About nock

A community learning to work with AI, as software engineers, and the open-source toolbox they learn with.

Why it exists

A coding agent starts every session knowing nothing of the last one: not what was decided yesterday, or why; not what you said about it; not which script someone wrote to do what it is about to do by hand. Over weeks, the project drifts: the same question answered three ways, a simplification nobody approved, the same mistake made again.

The usual fix is prose: skills, notes, rules in CLAUDE.md. Prose goes stale without anyone noticing, and is read differently every time. A command that no longer fits the project breaks instead: it exits non-zero, a check fails, and the failure is recorded. So the toolbox can be kept honest by measuring it.

A check beats a hook beats prose. A rule that a check enforces cannot be ignored. A behavior that a hook triggers cannot be forgotten. Prose is the last resort.

Three principles

  1. An agent-friendly CLI. Every byte a command prints is read by a model and paid for: a command prints what the next decision needs, success is often silence, the exit code says what to do next, and a mistake gets an answer, not just a refusal.
  2. Every run recorded. Every call to nock and every Claude Code session is recorded on your machine: what was asked, each tool call, what failed, what it cost. You cannot improve what you have not measured, and agents do not remember.
  3. Reflection. Every so often an agent reads that record and improves the toolbox: it builds tools for the work that keeps costing turns, repairs the ones that misbehave and retires the ones nobody uses, and writes down what it expects each change to do.

Where you come in

You are there for the one thing no agent can infer: what the system is for. nock keeps your word where the next session finds it: every decision you accept or reject, every message in a thread, the map of what they mean for the work. Agents never wait on you, and nothing waits for you to be there.

Who makes it

nock is made by Parallel Labs, a company in Barcelona that also makes Logika. It is open source under the MIT License, standard-library Python with no dependencies, and vendored into the repositories that use it, so it is your project's own code: your agents can read it, and fix it if they must.

It is built in the open with the engineers who use it. What they learn — an insight, a feature, a new kind of reflection round — goes back into nock for everyone.

Getting started

From uvx nock init to your first verdict on what an agent made: seven steps, about ten minutes, in a repository of your own.

  • Step 1

    Install it in your repository

    Inside the repository, run uvx nock init (or pipx run nock init). It vendors nock into .nock/core/, writes .nock/config.toml, a primer CLAUDE.md imports, Claude Code's hooks and permissions, and the skills.

  • Step 2

    Commit it

    nock is your project's own code now, so it goes in git. Telemetry stays out: .nock/local/ is ignored, and never leaves your machine.

  • Step 3

    Make your tests the gate

    Add your test suite and linters as checks. Tools and reflection rounds must pass them, and .nock/nock check prints nothing when they do.

  • Step 4

    Work as you always do

    Start Claude Code and ask for something. Every session reads nock's primer through CLAUDE.md, starts with the project's tools listed once it has some, and is recorded: what you asked, each tool call, what failed, what it cost.

  • Step 5

    Your agent puts its work before you

    It opens a topic for the work, carries on, and submits what a later reader would ask "why" about: the choice it made, with what it weighed instead. It never waits on you.

  • Step 6

    Open the studio

    Run .nock/nock studio. Its Work tab lists the topics, newest activity first: what each holds, its verdicts, where the work stands.

  • Step 7

    Give your first verdict

    Open the decision, read the answer and what was considered instead, and accept it — or reject it, and the agent reworks it as its thread says. The first time, nock asks once whether to share a weekly usage report of counts; nothing is sent unless you say yes.

    • What happens next

    After 15 sessions or 7 days, a session start says a reflection round is due; run /nock-reflect in a session, and read its report. Your agents' tools grow from there.
