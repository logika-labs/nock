# The nock.toolbox subround

Start the run with `.nock/nock reflect nock.toolbox`, or pick up the one under way: it prints the run's material, its agents with their briefs, the files to write and the submit.

Set aside whatever this session was doing: the subround works from its
material, not from memory.

1. Dispatch the `nock-toolbox` subagent with its material (below) and the
   run's window. It improves the project's `.nock/` toolbox from its
   telemetry, reading its own brief; it commits nothing. If it fails, say so
   in the report; don't do its part yourself.
2. Write `report.md` for the owner: what changed in the toolbox and why,
   and what should be measurably different by the next run. Only what
   they would act on or want to know.
3. Submit with the part's changes (kinds add, change, retire, check,
   other) and its verdicts on the last run's expectations. It runs nock's
   checks and refuses while one fails: fix it, or have the part fix it, and
   submit again. A command the part added fails `nock-wiring` until
   `.nock/nock init` allows it; Claude Code asks the owner for that. It
   commits the toolbox and the record.
4. Report the subround in your final message, to the session that ran it:
   what changed in the toolbox and why, what needs the owner (the commands
   `.nock/nock init` should allow), and where `report.md` is.
